## Check 3 — MCC CI defect diagnosis (root cause isolated)
`part7.py` line 20: `den = math.sqrt(max((tp+fp)*(tp+fn)*(tn+fp)*(tn+fn), 1e-12))` where the counts are
**numpy int64** from `rs.multinomial(n, freq)`. Product ≈ 4.089e19 > int64 max 9.223e18 → silent wraparound
(numpy emits `RuntimeWarning: overflow encountered in scalar multiply`).
Replicated the notebook code path exactly (n_boot=1000, `_dseed('LogReg(C=4.0)',11)`): reproduced the
reported **[3.0322, 3.0428] bit-for-bit**. Same seed with float arithmetic gives the correct CI **[0.9482, 0.9512]**,
which brackets the point estimate 0.949715. Point estimates (from `clf_metrics`/sklearn) are unaffected —
only the 3 bootstrap MCC CIs (CSV + TeX) are garbage. Fix (if a revision is authorized): cast to float before
the product, e.g. `den = np.sqrt(float(tp+fp)*float(tp+fn)*float(tn+fp)*float(tn+fn))`.
