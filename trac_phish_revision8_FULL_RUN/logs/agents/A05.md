## Notes on leakage implications

1. **PP_train ∩ PP_test = 0 (exact URLs).** PhreshPhish's temporal split (train ≤ 2025-09-08 < test) produces zero exact-URL leakage — clean for cross-corpus transfer evaluation.
2. **Cross-corpus exact-URL overlap is negligible (≤ 47 URLs, ≤ 0.014% in any direction).** Any GB↔PP contamination at the exact-URL level is immaterial; GB and PP are effectively disjoint corpora at URL level.
3. **GB internal exact-URL overlap is small but nonzero: 317 URLs (0.198% of GB_test).** GramBeddings' train/test split leaks a tiny set of duplicated exact URLs — negligible for aggregate metrics but worth noting for per-URL-level analyses.
4. **Hostname-level GB_train∩GB_test overlap is substantial: 50,997 hosts = 39.76% of GB_test hosts.** Under any hostname-aware feature (registrable domain, eTLD+1) or model that generalizes by host, GB's own test evaluation is optimistic: roughly 4 in 10 test hosts were already seen in train. This is *host generalization*, not exact-URL leakage — expected for this dataset's random split, but a caveat when citing GB test AUC as "unseen-host" performance.
5. **Implication for TRAC-Phish Rev8:** cross-corpus transfer (GB→PP, PP→GB) is a valid "near-zero train/test contamination" design at exact-URL level; in-corpus GB results should be annotated with the 39.76% host-overlap caveat. Recommend downstream agents (evaluation stage) report both exact-URL and host-level contamination caveats.
