Key scaling facts:
- nnz/doc ≈ 255 raw (URL mean length 66.3 chars; median 49, p99 296). Raw nnz scales linearly: 576k docs → ~147M raw (doc,term) pairs.
- Vocabulary grows sublinearly (Heaps β≈0.66): ~6.9–7.4M distinct terms at 576–640k docs → Python dict + string objects ≈ 650–750 MB during fit.
- min_df=20 at full scale is a weak filter (ratio 3.5e-5): df-analysis at 60k shows df≥2 (same ratio) retains ~93.5% of nnz. Final matrix ≈ 130–140M nnz even after pruning/max_features=400k.

Peak-memory extrapolation to the train fold (576k docs):
- **Default dtypes (CountVectorizer default dtype=np.int64, confirmed in sklearn 1.5.2 source line 1169):** raw CSR ≈ 147M×12B = 1.76 GB; plus transient j/values arrays during `_count_vocab` construction (≈8B×147M ≈ 1.2 GB, coexist briefly); plus ~0.7 GB full-vocab dict; plus `_limit_features` building the pruned matrix while the raw one is alive. Marginal-rate extrapolation from 60k/120k/240k probes: peak ≈ **5.5–6 GB → certain OOM** (available 3.6 GB).
- **With dtype=np.float32:** peak ≈ **4.3–4.5 GB → still OOM.**
- Post-fit steady state: train matrix alone ≈ 130–140M nnz → 1.6 GB (float64) or 1.1 GB (float32); plus val (64k) and test (160k) transforms ≈ +0.15/+0.38 GB if held simultaneously.

### Required memory changes (mandatory before execution)
1. `TfidfVectorizer(..., dtype=np.float32)` — halves all matrix memory (counts are built as int32 anyway in `_count_vocab`; TfidfTransformer preserves float32).
2. **Two-stage fixed-vocabulary fit:** select the vocabulary on a ~120–150k-doc random subsample of the train fold (min_df=20, max_features=400k there → ~190–250k terms), then `TfidfVectorizer(vocabulary=fixed_vocab, dtype=np.float32).fit_transform(full_train_fold)`. Peak ≈ 2.5–2.8 GB (no full 7M-term dict, no prune-time double matrix). Document this explicitly as a memory-forced deviation from the reconstructed-spec default (min_df semantics approximately preserved; df threshold effectively evaluated on the subsample).
3. Transform val/test in ≤100k-row chunks with `del` + `gc.collect()` between stages; never hold train+val+test matrices simultaneously; persist matrices with `scipy.sparse.save_npz(compressed=True)` (~300–500 MB each; 9.3 GB free disk → rotate checkpoints, keep hashes, delete superseded ones).
4. **Do not load PhreshPhish train (498k rows)** — zero-shot transfer needs only its 168k test parquet. Loading both GramBeddings full + PhreshPhish train in one kernel risks OOM independent of TF-IDF.
5. **SHAP must never materialize dense values in TF-IDF space** (160k×400k float32 ≈ 256 GB). Analytic linear-SHAP on ≤2–5k sampled test rows, computed sparsely (top-k |coef| features, or aggregate per-row |contribution| summaries); TreeExplainer only for the 30-feature HistGB (fine).
6. Optional further headroom if instability persists: start ngram_range at 2 (drops ~14% nnz; 1-grams carry little signal beyond the ~30 lexical features) and/or max_features=200k.

Secondary resource notes:
- Fit time is fine (~2–3 min for the vectorizer at 576k). LogReg (lbfgs) on ~130M nnz ≈ 5–15 min/config. **LinearSVC (liblinear, single-thread) on 130M nnz may run 30–90+ min** — set max_iter a-priori and honestly report non-convergence in the negative-results ledger if hit.
- Small MLP must be trained on the ~30 lexical features (or heavily reduced TF-IDF), never raw TF-IDF.

## 2. Leakage risks (protocol)

- **Vectorizer fitting:** must be fit on the train fold only; transform val and test. The listed order (partition → TF-IDF) is correct but the notebook must make fit/transform boundaries explicit. Never fit on train+val+test jointly.
- **Refit-after-selection:** if the final model is refit on train+val before test eval, calibration must then use a fresh split. Simplest safe path: train on the 90% fold, select+calibrate on val, evaluate test exactly once, no refit.
- **Calibration:** Platt/isotonic fit on val (or a held-out slice of train) — **never on test**. ECE/Brier reported on val (selection) and test (final) separately, labeled as such.
- **Dedup/normalization:** dedup happens before partition ✓, but define URL normalization (lowercasing, scheme/`www` stripping, trailing punctuation) a-priori and apply consistently; report duplicates with conflicting labels rather than silently dropping.
- **Train/test contamination:** quantify exact + normalized overlap between GramBeddings train and test before any eval; report raw and overlap-excluded metrics if overlap > 0. Test set must be touched exactly once.
- **Rules model / thresholds:** rules and all decision thresholds fixed a-priori from train only; phase-gate thresholds committed to manifest before test eval.
- **SHAP background sample:** from train fold only, not test.
- **PhreshPhish transfer:** strictly zero-shot — reuse the fitted vectorizer and lexical extractor; no refit, no threshold tuning on PhreshPhish (fixed 0.5 / a-priori operating point).
- **Label-shuffle null:** run on train/val, never on test.

## 3. Determinism risks

- `LinearSVC` (liblinear) accepts **no random_state** and is nondeterministic with >1 OpenMP thread → pin `OMP_NUM_THREADS=1` (or threadpoolctl) for that stage. LogReg(solver='liblinear') does take random_state — set it; prefer lbfgs (deterministic).
- MLP: set `random_state` (weight init, adam, and the internal early-stopping split which consumes random_state); fix BLAS threads for reproducible arithmetic.
- HistGradientBoosting: set `random_state` (early-stopping subsample draws from it).
- Fix env once at kernel start: `PYTHONHASHSEED`, `OMP_NUM_THREADS`, `OPENBLAS_NUM_THREADS`, `MKL_NUM_THREADS` (record values; hash seed must be set before interpreter start to be effective — note this caveat in the reproducibility report).
- Fixed seeds for: stratified split, bootstrap CIs, label-shuffle null, SHAP/perturbation/case-study sampling. Record all in the manifest.
- Vocabulary order is insertion-order dependent (document order) → deterministic given fixed data order; keep row order stable after dedup (sort by hash before split to be safe).
